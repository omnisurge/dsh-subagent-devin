# 文案变更表（M2：未配置/未登录状态）

范围：设置页「Devin 子代理」→ 连接卡片的下半部分。**结构不变**：不新增控件，
「检查连接」按钮改为始终可点（未配置时点击 = 重新检测 CLI 登录状态）。
所有句子由 Client 词典拥有；Host 只提供原因码。

| 位置 | 旧文案 | 新文案（中文） | 为什么 |
|---|---|---|---|
| 检查按钮下方状态行 | 只有绿点「已登录 · N 个可用模型」/「登录未成功」 | 增加第三态：红点「连接失败」 | 后端根本起不来时，之前什么都不显示，用户以为没反应 |
| 原因 · CLI 未登录 | 无（页面什么都不说） | 「本机 Devin 还没有登录，也没有已保存的密钥。两种做法：在终端运行 devin auth login 登录一次，回来点「检查连接」；或者直接把 devin- 开头的密钥粘贴到上面。」 | 用户不知道下一步做什么 |
| 原因 · 凭据文件里没密钥 | 无 | 「没在本机 Devin 的凭据文件里找到密钥。可以粘贴密钥，或先在本机运行一次 devin auth login。」 | 同上，且区分「没登录」与「登录了但文件里没有」 |
| 原因 · 自动导入被关 | 无 | 「自动导入已关闭。请粘贴密钥。」 | 用户自己关的开关要能被解释 |
| 原因 · 导入失败 | 无 | 「从本机凭据导入失败。请直接粘贴密钥，或查看应用日志了解原因。」 | 不把「读不到」写成「没有」 |
| 原因 · 认证被拒 | 无 | 「密钥没有被接受。确认用的是 devin- 开头的那把；apk_user_ 开头的是平台接口密钥，不能用作子代理登录。」 | 用户当前正踩这个坑 |
| 原因 · 命令行起不来 | 无 | 「找不到可用的 Devin 命令行程序，请检查插件设置里的路径。」 | 路径配错是最常见的安装问题 |
| 原因 · 握手无响应 | 无 | 「Devin 命令行没有正常应答，请稍后再试。」 | 与「没登录」区分开 |
| 密钥来源行 | 无 | 「密钥来自本机 Devin 的登录凭据。」 | 让用户知道这把钥匙是哪来的 |
| 权限提示行 | 无 | 「该凭据文件同机其他账号可读，建议 chmod 600 收紧权限。」 | 实测当前是 644 |
| 原始诊断 | 无 | 「原始诊断：<技术信息>」（灰字、小号、默认折叠在最后） | 提供排查线索，但不挤占主文案 |
