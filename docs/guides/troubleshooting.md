# 排查

## 先看页面在说什么

设置页的「连接」卡会把原因直接写出来。原因码到含义的对照：

| 页面提示 | 真正发生了什么 | 怎么办 |
|---|---|---|
| 本机 Devin 还没有登录 | 凭据库里没有密钥，CLI 也报未登录 | 在终端跑卡片上的登录命令，或粘贴 `devin-` 的密钥 |
| 没在本机 Devin 的凭据文件里找到密钥 | CLI 说已登录，但文件里读不到值 | 在终端跑登录命令刷新一次，或直接粘贴 |
| 找不到可用的 Devin 命令行 | 配置的路径不存在，PATH 里也没有 | 在插件设置里填 CLI 绝对路径 |
| Devin 命令行没有正常应答 | 进程起来了但没完成握手 | 隔一会儿重试；持续如此看下面的诊断 |
| 密钥没有被接受 | ACP 认证被拒 | 确认用的是 `devin-` 开头的那把（`apk_user_` 不行） |
| 自动导入已关闭 | 配置 `importFromCli: false` | 改成 `true`，或直接粘贴 |
| 从本机凭据文件导入失败 | 读到了但写入凭据服务失败 | 看应用日志；可直接粘贴绕开导入 |
| 凭据库里有记录但读不到值 | 凭据服务里是空值 | 重新保存一次密钥 |
| 应用的凭据服务不可用 | 宿主没有提供凭据服务 | 重启应用；仍不行说明宿主版本不对 |
| 还没找到凭据文件 | 目录或文件还没生成 | 先登录一次 Devin，文件才会出现 |

## 常见症状

**改完设置没生效、按钮点了没反应**
链接安装（`link:`）下改源码不会替换已加载的模块，必须重启应用；页面本身刷新即可拿到新客户端文件。

**一直显示未连接，但终端里 `devin auth status` 是已登录**
先点「重新检测」。如果还是不行，多半是插件跑 CLI 时超时了——本插件的读法是「stdin 接 /dev/null、8 秒超时」，真机上一次状态查询约 2 秒。

**登录命令跑完浏览器没开**
Devin CLI 的登录是交互式菜单，会自己打开浏览器；如果终端里没反应，换一个真正的终端窗口（IDE 内嵌终端有时会挡住）。

**凭据文件被其他账号可读**
页面会提示 `chmod 600`。这不在插件职权内自动改，需要你自己决定。

## 诊断命令

```sh
devin auth status            # 是否登录、凭据文件在哪、账号名
devin models list --format json | head -40   # CLI 自己列的模型（按需）
ls -l ~/.local/share/devin/credentials.toml  # 权限是否为 600
```

插件页面上的「打开凭据文件位置」等价于：

| 平台 | 命令 |
|---|---|
| macOS | `open -R <凭据文件>` |
| Windows | `explorer /select,<凭据文件>` |
| Linux | `xdg-open <凭据文件所在目录>` |

## 不要做的事

- **不要**把密钥贴进 issue、日志或配置；配置里只应该有引用名。
- **不要**为了让它跑起来而改官方运行时或手工往 profile 里塞行；安装只用官方插件入口。
