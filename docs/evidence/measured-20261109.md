# 实测记录（2026-11-09，macOS）

只记当时量到的事实，不写结论性建议。命令附后，可复现。

## 1. 模型可用表是**会话级闸门**，与 CLI 自己的目录不是一回事

同一个账号、同一台机器：

| 来源 | 说你能用什么 |
|---|---|
| `devin models list`（CLI 目录） | 48 个家族；`swe-2-high` / `swe-2-medium` / `swe-2-max` 全在，标 `Free` |
| ACP 会话 `configOptions.model.options` | 132 项；SWE-2 只有 `swe-2-high`、`swe-2-flash-medium` |
| App 自己的设置文件 | `agentPreferences["devin-cli"].model = "swe-2-max"`（App 只存 `model` 一个键，没有单独的强度键） |

逐个 `session/set_config_option` 试探（同一会话内）：

| 模型 | 在可用表 | 结果 | 会话最终值 |
|---|---|---|---|
| `swe-2-high` | 是 | 接受 | `swe-2-high` |
| `swe-2-flash-medium` | 是 | 接受 | `swe-2-flash-medium` |
| `swe-2-medium` | 否 | 拒绝 | 不变 |
| `swe-2-max` | 否 | 拒绝 | 不变 |
| `swe-2-flash-max` | 否 | 拒绝 | 不变 |

结论性观测：**闸门是 `configOptions.model.options` 这份列表本身**，不是「模型是否存在」。

显示名（`value → name`）：`swe-2-high → SWE-2`、`swe-2-flash-medium → SWE-2 Flash`。
`high` 只存在于内部 id，不上屏。

## 2. 档位与模型是两条独立的轴

同一会话内反复切：

```
基线        : model=swe-2-high  thought=high    speed=standard
强度设 max  : model=swe-2-high  thought=max     speed=standard
强度设 中   : model=swe-2-high  thought=medium  speed=standard
试设 swe-2-max: model=swe-2-high  thought=medium  speed=standard   ← 被拒，两项都不变
```

改强度不改模型 id，改模型不改强度。

## 3. 页面写入真的落盘，并且热生效

- 08:43:25 用户在设置页把思考强度点成「最高」→ `cordis.patch.yml` 里出现 `thought: max`
- 08:45:40 起的一次子代理运行，会话日志出现 `session/set_config_option{config_id=thought_level}`
  （应用 08:43:03 启动、**没有重启**，说明 volatile 字段是就地生效的）
- 同一次会话 `config_id=speed` 出现 **0** 次——留空确实一个请求都不发
- 对照组：08:43:00–08:43:05 的启动探测会话里 `thought_level` 出现 0 次（探测只读不写）

## 4. 档位不是摆设：同一题 A/B（各跑两次）

题面固定：`计算 1!+2!+…+20! 的末两位数字。只回答两位数，不要解释。`

| 档位 | 耗时 | 思考文本字符 | 答案 |
|---|---|---|---|
| medium | 2833ms | 377 | 13 |
| max | 4199ms | 279 | 13 |
| medium | 2434ms | 347 | 13 |
| max | 4082ms | 248 | 13 |

- 耗时：`max` 稳定慢约 1.6 倍（4.1–4.2s vs 2.4–2.8s）→ 参数确实改变了后端行为。
- 思考文本字符：`max` 反而更短 → 多出来的时间不在「流给客户端的思考文本」上。
- 答案四次都是 13（正确），题目太简单，看不出质量差异。

## 5. 档位会改写会话的 `model`：与 App 里的 `swe-2-max` 是同一条记录

Devin App 的任务列表读的是 `~/.local/share/devin/cli/sessions.db` 的 `sessions.model`。
用受控实验（每个组合各开一个会话、发一句 prompt 让它落库）量到：

| 设置 `model` | 设置 `thought_level` | 会话报告 `configOptions.model.currentValue` | **落库的 `sessions.model`** |
|---|---|---|---|
| `swe-2-high` | `high` | `swe-2-high` | `swe-2-high` |
| `swe-2-high` | `medium` | `swe-2-high` | **`swe-2-medium`** |
| `swe-2-high` | `max` | `swe-2-high` | **`swe-2-max`** |
| `swe-2-flash-medium` | `high` | `swe-2-flash-medium` | `swe-2-flash-medium` |
| `swe-2-flash-medium` | `medium` | `swe-2-flash-medium` | `swe-2-flash-medium` |
| `swe-2-flash-medium` | `max` | `swe-2-flash-medium` | **`swe-2-flash-max`** |

结论（观测，不是推测）：

1. `swe-2-high + thought_level=max` 与 App 里的 `swe-2-max` **是同一条记录、同一个值**。
   App 的「SWE-2 Max」就是这么显示出来的。
2. 会话内 `configOptions.model.currentValue` **不变**，变的是持久化的 `sessions.model`
   ——所以只看会话报告会以为「没生效」，看落库才知道生效了。日志里设档位的关键 span 叫
   `set_session_config_option{config_id=thought_level}:apply_model_change`，与此一致。
3. 映射**不是**简单的「换后缀」：`swe-2-flash-medium + high` 与 `+ medium` 都不改 id，
   只有 `+ max` 才变成 `swe-2-flash-max`。原因未查明，只记事实。

查法：

```sh
cp ~/.local/share/devin/cli/sessions.db* /tmp/x/ && sqlite3 -header -column /tmp/x/sessions.db \
  "SELECT substr(working_directory,-14) AS dir, model FROM sessions WHERE working_directory LIKE '%devin-eq-%';"
```
