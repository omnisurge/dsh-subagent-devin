# ADR-002：设置页与 Host 之间用「配置计数 + 行重载」，不自建 RPC

- 日期：2026-11-07
- 状态：accepted
- 关联：[ADR-001](ADR-001-provider-and-settings-page.md)、[SPEC 第 7 节](../specs/devin-subagent.md)

## 背景

设置页需要两件只有 Host 才能做的事：

1. **重新检测**：跑一次 CLI 状态查询 + ACP 握手，把账号、模型列表、失败原因写回来。
2. **打开凭据文件位置**：调系统文件管理器定位 `credentials.toml`。

官方 Client 面能直接调的只有 `remote.credentials` 和 `remote.settings`（读写配置），
没有「让本插件在 Host 侧执行一个方法」的公开通道。自建通道要么走 `@Remote` 装饰器
（需要 typert 编译产物，未验证手写 spec 能否被网关接受），要么另造一条协议。

## 决策

**用现有配置字段当触发器，不新增 RPC 层。**

| 动作 | 做法 |
|---|---|
| 重新检测 | 页面把 `refreshToken` 递增写进配置 → 插件行重载 → 启动时探测 → 结果写回 volatile `probe` → 页面轮询到 `probe.at` 变化 |
| 打开位置 | 页面把 `revealToken` 递增 → 行重载 → 启动时执行系统命令 → 结果写回 `probe.revealReason` |
| 保存密钥 | 直接 `remote.credentials.set`，不触发重载 |

`lastRevealToken` 记录已处理的请求，只有 `revealToken > lastRevealToken` 才动作，避免每次
重载都弹文件管理器。

## 后果

- **代价**：这两个动作会让插件行重载，界面闪一下；探测本身是异步的，页面靠轮询感知结果
  （40 次 × 500ms 上限）。
- **好处**：零新增协议面，不依赖未验证的 typert 生成链，Host 侧没有常驻守护逻辑；
  插件被禁用时触发器自然失效，不会留下悬挂的回调。
- **失败可见**：探测结果与打开结果都落在 `probe` 里，页面能如实显示，而不是一律报成功。
- **限制**：不适合高频动作，也不适合需要即时返回值的交互。真的需要双向 RPC 时再评估 typert。

## 被否掉的方案

- **手写 typert spec 声明 `remote.<ns>`**：官方套件用过这条路，但它依赖编译产物，
  当前运行时下能否被网关接受未验证；为一个页面引入这条链，风险与收益不成比例。
- **页面轮询触发**：让 Host 定时看配置变化，等于常驻轮询；插件禁用后依然在跑。
- **把动作塞进 `probe` 字段**：把「请求」和「结果」混在同一个对象里，语义混乱，且每次
  探测都会覆盖它。
